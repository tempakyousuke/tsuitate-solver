# 衝立 df-pn ソルバー 最適化ガイド

## 現在の最適化状況

### 実装済み

1. **proof_hand（証明駒）追跡**
   - OR/AND ノードごとに証明に必要な最小の攻め方持ち駒を計算・伝播
   - OR: 証明された AND 子の proof_hand の要素ごと min
   - AND: 各分岐の proof_hand を親の hand から逆算して要素ごと max

2. **優越関係テーブル（dominance table）**
   - `meta_board_set_hash`（盤面+gote_hand のハッシュ集合）→ Pareto最小の proof_hand
   - チェック: `proof_hand[j] <= sente_hand[j]` (全要素) なら証明済み
   - ハッシュ生成: 個別ハッシュをソートしてから結合（XOR より衝突耐性が高い）

3. **df-pn 順序修正**
   - `mid_or`/`mid_and` ループ内で終了判定（pn==0 or dn==0）をしきい値チェックの前に配置
   - これにより proof_hand 計算と dominance 登録が pn=0 確定時に確実に実行される

4. **無駄合い判定**
   - `is_futile_interposition`: 再帰的判定（深さ3まで）
   - キャッシュ: 打ち駒の同一マスのみキャッシュ（盤上移動はキャッシュ不可）

5. **候補手ソート・フィルタ**
   - 打ち駒優先 → 玉に近い手 → 合駒マス数の少ない手
   - 長距離王手の合駒マス上限（4マス）
   - プローブ手（一部の盤面でのみ合法な手）の自動生成

6. **Board-Only Move Hint（手順ヒント）**
   - 盤面配置のみのハッシュ（持ち駒除外）で証明された手を記録
   - 同じ盤面で持ち駒が異なる MetaPosition に対してヒントとして適用
   - 候補手の並べ替えのみで正確性に影響なし（dominance ではなく hint）
   - 合駒取り返し後の類似分岐で効果的（問題25: 692→157ノード、-77%）

### ベンチマーク基準値（通常モード）

- 41/41 問正解、合計 44.4s、57,020 ノード
- 最難問（問題8）: 41.8s / 48,202 ノード

## board-only ハッシュが使えない理由

### 試みた内容

`hash_without_sente_hand` から gote_hand も除外し、盤面配置のみでハッシュを計算する方式を試行。目的は異なる持ち駒構成の MetaPosition 間で dominance マッチを可能にすること。

### 失敗の原因: 観測構造の依存性

衝立詰将棋では、gote の持ち駒が異なると**観測（Observation）の分岐構造**が変わる。

```
例: 5三飛で王手 → gote が合駒
  gote に飛車あり → 飛車で合駒 → sente が取り返す → 観測構造 A
  gote に飛車なし → 歩で合駒のみ → sente が取り返す → 観測構造 B（分岐が減る）
```

証明木は観測ごとに分岐するため、観測構造が異なると証明戦略を転用できない。
これが完全情報ゲーム（通常の詰将棋）との根本的な違いであり、「持ち駒が多い方が有利」
という単純な dominance が成立しない理由。

### 教訓

- **gote_hand は dominance ハッシュに必須**（観測構造を保存するため）
- board-only ハッシュ + S_proven チェック（S_new >= S_proven）は理論的には駒数保存則
  で正しいが、観測構造の変化を考慮していないため unsound
- 問題8 で無限ループ（正常時 42s → board-only で 120s+ タイムアウト）として顕在化

## aigoma.json の最適化課題

### 問題の構造

```
  5  4  3  2  1
          v金v玉  1
              .   2
 ^飛v歩^金  .  .  3
     ^桂        .  4
攻め方持ち駒: なし
```

sente の持ち駒がない → gote の持ち駒が豊富（飛角金銀桂香歩など）。
5三飛で王手すると、gote は様々な駒で 2二や 3二に合駒できる。

### 合駒取り返し後の状況

sente が合駒を取り返した後:
- **盤面**: 全バリアント（飛合、角合、銀合…）で同一
- **sente_hand**: 取った合駒の種類により異なる（例: base+飛 vs base+角）
- **gote_hand**: 対応して異なる

これらは AND ノード内の異なる観測分岐として展開され、それぞれ独立に探索される。

### なぜ dominance でマッチしないか

1. **gote_hand が異なる** → `hash_without_sente_hand` が異なる → テーブルで同一グループにならない
2. **sente_hand が非comparable** → base+飛 と base+角 は要素ごとの ≥ 関係を満たさない
3. 仮に board-only ハッシュを使っても、上記 2 の理由でマッチしない

## 今後の改善アプローチ

### アプローチ 1: 証明戦略リプレイ（Proof Strategy Replay）

**概要**: 証明された MetaPosition の証明木（手順）をキャッシュし、類似の MetaPosition に対してリプレイを試みる。リプレイ中に全ての手が合法で全ての観測が一致すれば、証明を転用できる。

**利点**:
- 観測構造の一致を明示的に検証するため、理論的に安全
- hand の comparable 性に依存しない
- 合駒取り返し後のケースに適用可能

**実装イメージ**:
```rust
// mid_or で dominance チェックの後に追加
fn try_replay_proof(
    &self,
    meta: &MetaPosition,
    proof_tree: &SolutionNode,
) -> bool {
    // proof_tree の各手を meta に適用
    // 1. 手が全盤面で合法か確認
    // 2. 各観測分岐が proof_tree と一致するか確認
    // 3. 再帰的に全分岐をチェック
    // 全て一致すれば true
}
```

**課題**:
- 証明木のキャッシュメモリ
- リプレイの計算コスト（各ノードで全候補を試すと高価）
- どの証明木を試すかの選択ヒューリスティック

**キャッシュキー案**: `meta_board_set_hash`（gote_hand 除外版 = board-only）をキーにして証明木を格納。同じ board-only ハッシュの MetaPosition に対してリプレイを試みる。

### アプローチ 2: AND ノード内分岐統合（Branch Merging）

**概要**: `mid_and` 内で、同じ board 構成を持つ複数の観測分岐を検出し、1つを解いたら他に証明をリプレイする。

**利点**:
- 合駒取り返し後の分岐は同一 AND ノード内に存在するため、自然な適用ポイント
- リプレイ範囲が限定的（同一 AND ノード内）でコスト制御しやすい

**実装イメージ**:
```rust
// mid_and 内で観測分岐を構築した後
// 同じ board-set-hash を持つ分岐をグルーピング
// グループ内の1つが pn=0 になったら、他の分岐にリプレイ
```

**注意**: 観測構造が一致することの明示的検証が必要。

### アプローチ 3: MetaPosition レベルの高度な無駄合い判定

**概要**: 現在の per-position 無駄合い判定を拡張し、MetaPosition 全体で「全ての合駒バリアントが無駄」であることを一括判定する。

**着眼点**: aigoma.json では gote の合駒が豊富だが、多くは無駄合いになる。現在は各 Position 内で独立に無駄合いを判定しているが、MetaPosition 内の複数 Position にまたがるパターンを検出できれば、expand_defense_moves の出力を大幅に削減できる。

**実装イメージ**:
- 合駒マスと取り返し手が MetaPosition 内の全 Position で共通かチェック
- 共通なら、代表 Position 1つで無駄合い判定を行い、結果を全 Position に適用
- 非共通なら従来通り個別判定

### アプローチ 4: 観測非依存証明の検出

**概要**: 証明木内で「どの観測が来ても同じ手を指す」区間を検出する。そのような区間は gote_hand に依存しないため、hand が異なる MetaPosition にも転用できる。

**例**:
```
▲2二金打 → (全観測で) → ▲3一金 → ...
```
この手順が全ての観測分岐で共通なら、gote_hand が異なっても同じ手順が使える。

**利点**:
- 特別なリプレイ検証が不要（観測に依存しない ≒ 常に成立）

**課題**:
- 実際にそのようなケースがどの程度あるか要調査
- 部分的な観測非依存性（一部の分岐のみ共通）の扱い

### アプローチ 5: 手駒正規化（Hand Normalization）

**概要**: sente_hand の特定の駒種を「汎用駒」に正規化してハッシュを計算する。例えば、飛と角をまとめて「大駒1つ」として扱う。

**利点**:
- base+飛 と base+角 が同一ハッシュになり、dominance でマッチ可能に

**課題**:
- 正規化後の dominance が安全かの証明が困難
- 使われない駒種（例: 証明に飛も角も不要）の場合のみ安全
- proof_hand が [0,...] なら安全（その駒種を使わないため）

**実装案**: proof_hand[i] == 0 の駒種 i については、sente_hand[i] の具体的な値を無視（ハッシュ計算時に 0 として扱う）。これにより「証明に使わない余剰駒」が異なるだけの MetaPosition がマッチする。

ただし、この方式は proof_hand が判明した後にしか使えないため、探索の初期段階では効果がない。

## 優先度の提案

| 優先度 | アプローチ | 難易度 | 期待効果 | 安全性 |
|:------:|:---------:|:------:|:--------:|:------:|
| 1 | AND ノード内分岐統合 | 中 | 高（aigoma直接対応） | 明示的検証で安全 |
| 2 | 証明戦略リプレイ | 高 | 高（汎用的） | 明示的検証で安全 |
| 3 | MetaPosition レベル無駄合い | 低〜中 | 中 | 安全 |
| 4 | 観測非依存証明 | 中 | 不明（要調査） | 安全 |
| 5 | 手駒正規化 | 低 | 限定的 | 条件付きで安全 |

最も効果が高いのは**アプローチ 1 または 2**（証明のリプレイ）。aigoma.json のような合駒問題は、取り返し後の各分岐が非常に似た証明構造を持つため、1つの分岐の証明を他の分岐にリプレイすることで大幅な探索削減が期待できる。

## 参考: 衝立詰将棋固有の制約

通常の詰将棋の最適化手法を衝立詰将棋に適用する際は、以下の制約に注意:

1. **観測構造依存**: gote の持ち駒が変わると合法手が変わり、観測分岐が変わる
2. **MetaPosition の同一性**: 同じ盤面セットでも sente_hand が異なれば別の MetaPosition（sente は自分の持ち駒を観測できる）
3. **不完全情報**: sente は gote の応手を直接観測できない。得られる情報は Checkmate/Captured/NoCapture/Illegal の4種のみ
4. **証明の転用条件**: 盤面 AND gote_hand AND 観測構造 が全て一致する場合のみ安全
